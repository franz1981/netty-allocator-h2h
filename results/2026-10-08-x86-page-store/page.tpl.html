Netty page store vs mimalloc port vs pooled, x86

lao's full matrix (ByteBufAllocatorAllocPatternBenchmark, 32 threads, 2 forks, 10×1 s warmup, 10×1 s measurement) on Netty adaptive-page-store @ 34eff301a2, mimalloc port 1.2.4-SNAPSHOT (neoionet/netty-allocator 082a6d9). Ryzen 9 7950X, NUMA node 0 (8 cores / 16 threads), 2.3 GHz, JDK 25.0.3, 2026-10-08.

How it ran
  • JVM flags (harness defaults + ours): -server -dsa -da -XX:InitialRAMPercentage=40.0 -XX:MaxRAMPercentage=40.0 -Dio.netty.leakDetection.level=disabled -XX:MaxRAM=60g --enable-native-access=ALL-UNNAMED -XX:+ExitOnOutOfMemoryError, plus -prof gc; platform threads: -Djmh.executor=PLATFORM.
  • Page store, mmap off: -Dio.netty.allocator.segmentRegionSize=0 (malloc'd 4 MiB blocks), direct only: heap does not use mmap.
  • JDK 25 because mmap needs JDK 22+ with native access; lao's published ARM run used JDK 21 and Netty 82bd38c.
  • numactl --cpunodebind=0 --preferred=0, CPU ceiling 2300 MHz, THP madvise, kernel 7.1.13.
  • Raw data: JMH-*.data (text, with RSS lines) and JMH-*.json next to this page; cells.csv is what the charts show.
